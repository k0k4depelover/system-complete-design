Curso Proyectos Glosario

Aplicación de conocimiento

Mini-proyectos para construir lo que estudiaste, en Java y Spring Boot. Cada uno trae una excusa, el diagrama de arquitectura, los endpoints antes de empezar, las dependencias justas y un paso a paso con las decisiones de diseño explicadas. Cada proyecto se construye solo, sin código de otro: tú lo construyes, lo subes a tu repositorio y lo enlazas desde su página.

Cómo es cada guía

Todas siguen el mismo orden, para que sepas dónde está cada cosa. La guía te acompaña como un tutor: explica por qué se toma cada decisión, no solo qué escribir.

  1. La excusa y el diagramaQué vas a construir y para qué, con el diagrama de arquitectura y el papel de cada pieza.
  2. Los endpoints, antes de empezarUna tabla con cada endpoint: método, ruta, qué hace y qué responde. Es tu mapa para no perderte.
  3. Las dependenciasSolo las coordenadas de Maven que hacen falta y para qué sirve cada una. Crear el proyecto no se explica.
  4. La infraestructuraEl docker-compose.yml o los manifiestos de Kubernetes, comentados.
  5. El paso a pasoCada paso dice qué decisión toma, qué alternativa descarta y qué puede salir mal.
  6. Decisiones guiadasAntes de los pasos importantes, una pregunta como las de los ejercicios del curso: eliges y la guía te explica.
  7. Cómo comprobar que funcionaPruebas, carga con Gatling y fallas inyectadas, con los números que deberías ver.
  8. Tu repositorioEl enlace va en la página del proyecto y es obligatorio: sin él, el proyecto no se marca como terminado.
  9. Cómo conectarAl final, y solo con proyectos anteriores de la lista: qué cambia si juntas este proyecto con uno que ya hiciste, con enlaces a los módulos y al glosario.
Java y Spring Boot en el backend
Todo el backend es Java. La única excepción es el servidor de autorización de A13, en TypeScript sobre Cloudflare Workers, porque Workers no ejecuta la JVM.
Cada proyecto se construye solo
Ninguna guía necesita el código de otra: cada una trae su compose o su clúster y su propia excusa. Las piezas se juntan solo en los dos sistemas completos, cada uno en su repositorio.
Nada de reinventar
Se usan las librerías estándar de Spring y de su ecosistema. Se programa a mano solo lo que enseña algo, como la tabla de claves de idempotencia o la verificación de una URL firmada.
Decisiones con fundamento
Cada decisión se apoya en un módulo del curso y en un número que vas a medir al final.
Frontend solo si enseña
Un HTML con JavaScript mínimo cuando el navegador es parte de la lección: cookies, subidas directas, claves de idempotencia y streaming.

El stack

El stack que definiste, más las herramientas para medir, probar y observar. Las guías publicadas usan Java 25, Spring Boot 4.1.1, PostgreSQL 18, PgBouncer 1.26 (en A07, el que trae CloudNativePG), Redis 8, Nginx 1.30, k3s 1.36 y CloudNativePG 1.30. Sus mediciones se tomaron con esas versiones, salvo un detalle: el código se compiló con el JDK 21, no con el 25, y corrió en contenedores con Java 25. Cada guía levanta solo lo que necesita: con 16 GB de RAM alcanza, pero el clúster, Elasticsearch y Ollama juntos no entran cómodos.

Índice de mini-proyectos

Uno por concepto clave, en el orden del curso. Los de núcleo son el mínimo; los de ampliación se escriben si los quieres. Cada uno enlaza los módulos donde está la teoría, y los que tienen guía muestran tu estado: sin empezar, en curso o terminado.

El plan por bloques

Las guías se escriben por bloques. Cada bloque se aprueba antes de empezar el siguiente.

    Sistemas completos

    Al final, dos sistemas que juntan varios proyectos en uno solo, con las decisiones de diseño que aparecen cuando las piezas tienen que convivir. Son los únicos que reutilizan lo que construiste, y cada uno tiene su propio repositorio.

    Decisiones tomadas

    Lo que se decidió antes de escribir las guías, y por qué.

    El servidor de autorización va en TypeScript
    Workers ejecuta JavaScript, TypeScript, Python y WebAssembly, no la JVM. A13 escribe el servidor en TypeScript y entra en la capa gratuita: D1 permite 5 millones de filas leídas y 100 000 escritas por día. Documentado Todo lo demás sigue en Java.
    Kafka entra al núcleo
    A09 enseña colas con Redis Streams y A18 enseña Kafka con los patrones de producción: topics de reintento con backoff, una DLQ y cómo reinyectar sus mensajes, y un consumidor idempotente.
    Un repositorio por proyecto
    El objetivo es saber hacer cada pieza, no armar un sistema grande. Cada proyecto tiene su repositorio, y C1 y C2 tienen el suyo, donde las piezas se juntan.
    Write-behind
    A03 implementa write-through para el precio y write-behind para el contador de visitas, que llega a PostgreSQL en lotes idempotentes aunque la aplicación se caiga a mitad de un lote.
    Kubernetes con k3s
    k3s corre dentro de Docker con un servidor, dos agentes y un registro de imágenes local. Trae Traefik, y la entrada se arma con Gateway API, porque ingress-nginx se retiró en marzo de 2026. Documentado
    Cada proyecto, independiente
    Ninguna guía depende del código de otra. "Cómo conectar", al final de cada guía, solo nombra proyectos anteriores de la lista, y las piezas se juntan de verdad en C1 y C2.
    Gatling y Testcontainers
    La carga se escribe con el DSL de Gatling en Java y las pruebas corren contra PostgreSQL y Redis de verdad, así que todo queda en el mismo lenguaje.
    Búsqueda y observabilidad
    Elasticsearch para A16, con Spring Data Elasticsearch. Prometheus, Grafana, Tempo y Loki con OpenTelemetry para A14: para empezar, la imagen grafana/otel-lgtm los trae juntos.

    Tutoriales de AI Engineering

    Una serie aparte, para construir sistemas con modelos de lenguaje: agentes, evals y RAG. Siguen el mismo orden que las guías de arriba, con dos diferencias. Van en Python, porque ahí están LangGraph, LangChain y el SDK de MCP. Y cada paso corre con dos modelos a la par: Claude por API y uno local en Ollama, para que compares calidad, costo y latencia con tus propios números.

    Un sistema que se rompe de verdad
    El agente no trabaja sobre datos inventados: cada tutorial levanta su víctima en Docker Compose, con métricas, logs y una base, y un script que provoca las fallas.
    Pruebas sin modelo, evals con modelo
    El grafo se prueba con pytest y un modelo falso con guion, sin red ni tokens. Lo que hace el modelo se mide aparte, con evals que repiten cada caso varias veces y cuentan pass^k.
    Leer es libre, actuar se aprueba
    Las herramientas de lectura corren solas. Todo lo que cambia algo pasa por una persona y lleva una clave de idempotencia, como enseña M25.
    Claude o local, con una variable
    Claude Sonnet 5.5 cobra por token; qwen3:8b en Ollama corre en tu máquina, sin costo por token, y pide unos 5.2 GB de descarga. Documentado Puedes seguir cada tutorial con uno solo de los dos.
